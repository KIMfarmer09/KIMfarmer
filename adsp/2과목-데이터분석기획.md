# 2과목. 데이터 분석 기획 (10문항 / 20점)

> 암기 과목입니다. 특히 **표로 된 분류(사분면, 단계 이름)** 가 그대로 문제로 나와요. ⭐ = 시험 단골.

---

## 1장. 데이터 분석 기획의 이해

### 1-1. 분석 주제 유형 4가지 ⭐⭐ (매회 출제 수준)
**분석 대상(What)** 을 아는지 × **분석 방법(How)** 을 아는지로 나눕니다.

| | 분석 대상 **안다** | 분석 대상 **모른다** |
|---|---|---|
| 분석 방법 **안다** | **최적화** (Optimization) | **통찰** (Insight) |
| 분석 방법 **모른다** | **솔루션** (Solution) | **발견** (Discovery) |

> 💡 외우는 법: 둘 다 알면 "최적화", 둘 다 모르면 "발견". 대상만 알면 방법(솔루션)을 찾고, 방법만 알면 통찰을 얻는다.

### 1-2. 목표 시점별 분석 기획
| 과제 중심적 접근 | 장기적 마스터 플랜 |
|---|---|
| 당면 과제를 **빠르게** 해결 (**Quick-Win**) | 지속적인 분석 문화 내재화 |
| Speed & Test, 문제 해결(Problem Solving) | Accuracy & Deploy, 문제 정의(Problem Definition) |

### 1-3. 분석 기획 시 고려사항
1. **가용 데이터** (데이터 유형 파악: 정형/반정형/비정형)
2. **적절한 활용 방안과 유즈케이스** (기존 사례 활용)
3. **장애 요소에 대한 사전 계획** (비용, 정확도, 교육 등)

## 2장. 분석 방법론 ⭐

### 2-1. 방법론 모델
- **폭포수 모델**: 단계를 순서대로, 이전 단계 완료 후 다음 단계 (하향식)
- **프로토타입 모델**: 일단 빠르게 만들어 보고 고객 피드백으로 개선 (상향식)
- **나선형 모델**: 반복하며 점진적 개발 (위험 관리에 유리, 복잡할 수 있음)

### 2-2. KDD 분석 방법론 (5단계) ⭐
**데이터셋 선택 → 데이터 전처리 → 데이터 변환 → 데이터 마이닝 → 결과 해석 및 평가**

> 💡 "잡음·이상치·결측치 처리"는 **전처리**, "차원 축소·변수 선택"은 **변환** 단계

### 2-3. CRISP-DM 방법론 (6단계) ⭐
**업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개**

- 4레벨 구조: **단계(Phase) → 일반화 태스크 → 세분화 태스크 → 프로세스 실행**
- 단계 간 **피드백(되돌아가기)** 이 가능
- 💡 "모델 과적합 문제 확인"은 **모델링** 단계, "모델이 업무 목적에 맞는지 평가"는 **평가** 단계

### 2-4. 빅데이터 분석 방법론 (5단계) ⭐
**분석 기획 → 데이터 준비 → 데이터 분석 → 시스템 구현 → 평가 및 전개**

- 3계층: **단계(Phase) → 태스크(Task) → 스텝(Step)**
- 각 단계 세부 내용
  | 단계 | 주요 태스크 |
  |---|---|
  | 분석 기획 | 비즈니스 이해 및 범위 설정, 프로젝트 정의·수행계획, **프로젝트 위험계획 수립** |
  | 데이터 준비 | 필요 데이터 정의, 데이터 스토어 설계, 데이터 수집·정합성 점검 |
  | 데이터 분석 | 분석용 데이터 준비, 텍스트 분석, 탐색적 분석(EDA), 모델링, 모델 평가·검증 |
  | 시스템 구현 | 설계 및 구현, 시스템 테스트 및 운영 |
  | 평가 및 전개 | 모델 발전 계획 수립, 프로젝트 성과 평가·보고 |

- **위험 대응 방법 4가지**: 회피(Avoid), 전이(Transfer), 완화(Mitigate), 수용(Accept)

## 3장. 분석 과제 발굴

### 3-1. 하향식 접근법 (Top-Down) ⭐
문제가 **주어진** 상황에서 해법을 찾는 방식
**문제 탐색 → 문제 정의 → 해결 방안 탐색 → 타당성 검토**

- **문제 탐색 도구 — 비즈니스 모델 캔버스** 5영역: **업무, 제품, 고객, 규제와 감사, 지원 인프라**
- **분석 기회 발굴 범위 확장** (관점 넓히기)
  - 거시적 관점 **STEEP**: 사회(Social), 기술(Technological), 경제(Economic), 환경(Environmental), 정치(Political)
  - 경쟁자 확대 관점: 대체재, 경쟁자, 신규 진입자
  - 시장 니즈 변화 관점: 고객, 채널, 영향자
  - 역량의 재해석 관점: 내부 역량, 파트너 네트워크
- **타당성 검토**: 경제적 타당성(비용 대비 효과), 데이터 및 기술적 타당성

### 3-2. 상향식 접근법 (Bottom-Up) ⭐
문제가 **정의되지 않은** 상황에서 **데이터부터 보며** 문제를 찾는 방식
- **디자인 사고**(Design Thinking): 발산(Diverge) ↔ 수렴(Converge) 반복
- **비지도 학습** 활용 (정답 없이 데이터 자체의 패턴 탐색)
- **프로토타이핑 접근**: 일단 분석해 보고 결과를 보며 개선 (시행착오)
- "Why(왜)" 보다 **"What(무엇)"** 관점

### 3-3. 분석 프로젝트 관리 — 5가지 속성 ⭐
**Data Size, Data Complexity, Speed, Analytic Complexity, Accuracy & Precision**

- **Accuracy(정확도)** vs **Precision(정밀도)**: 트레이드오프 관계인 경우가 많음
  - Accuracy: 모델과 실제 값의 차이가 적음 (과녁 중심 근처)
  - Precision: 여러 번 반복해도 결과가 일관됨 (탄착군이 모여 있음)
- **Analytic Complexity**: 정확도와 **해석 가능성** 사이의 균형점을 찾아야 함

### 3-4. 분석 과제 관리 10가지 영역 (ISO 21500 기반)
통합, 이해관계자, 범위, 자원, 시간, 원가, 리스크, 품질, 조달, 의사소통

## 4장. 분석 마스터 플랜

### 4-1. 우선순위 고려 요소
- **전략적 중요도**, **비즈니스 성과/ROI**, **실행 용이성**
- 적용 범위/방식 고려 요소: 업무 내재화 적용 수준, 분석 데이터 적용 수준, 기술 적용 수준

### 4-2. ROI 관점의 빅데이터 4V
| 투자 비용 요소 (난이도) | 비즈니스 효과 (시급성) |
|---|---|
| Volume, Variety, Velocity | **Value** |

### 4-3. 포트폴리오 사분면 분석 ⭐⭐ (매우 자주 출제)
가로축 = **시급성**(현재/미래), 세로축 = **난이도**(어려움/쉬움)

| | 시급성: 현재 (Current) | 시급성: 미래 (Future) |
|---|---|---|
| 난이도: **어려움** | **1사분면** | **2사분면** |
| 난이도: **쉬움** | **3사분면** | **4사분면** |

- **가장 먼저** 할 과제: **3사분면** (급하고 쉬움) / **가장 나중**: **2사분면** (안 급하고 어려움)
- **시급성**을 우선 기준으로 → **3 → 4 → 2**
- **난이도**를 우선 기준으로 → **3 → 1 → 2**

## 5장. 분석 거버넌스 체계

### 5-1. 거버넌스 구성요소 5가지
**조직(Organization), 과제 기획/운영 프로세스(Process), 분석 관련 시스템(System), 데이터(Data), 분석 관련 교육 및 마인드 육성 체계(Human Resource)**

### 5-2. 분석 준비도 (Readiness) — 6가지 영역 ⭐
**분석 업무 파악, 인력 및 조직, 분석 기법, 분석 데이터, 분석 문화, IT 인프라**

### 5-3. 분석 성숙도 (Maturity) ⭐
CMMI 모델 기반, 단계: **도입 → 활용 → 확산 → 최적화**
평가 부문: **비즈니스 부문, 조직·역량 부문, IT 부문**

### 5-4. 준비도 × 성숙도 사분면 ⭐⭐
| | 준비도 **낮음** | 준비도 **높음** |
|---|---|---|
| 성숙도 **높음** | **정착형** | **확산형** |
| 성숙도 **낮음** | **준비형** | **도입형** |

> 💡 외우는 법: 둘 다 낮으면 이제 **준비**, 둘 다 높으면 **확산**. 준비도만 높으면 바로 **도입** 가능, 성숙도만 높으면 **정착**이 필요.

### 5-5. 분석 조직 구조 3가지 ⭐
| 구조 | 특징 |
|---|---|
| **집중형** | 별도 분석 전담 조직이 전사 분석 수행. 현업 부서와 **업무 중복·이원화** 가능성 |
| **기능 중심형** | 각 현업 부서가 **직접** 분석. 전사적 관점 분석이 어려움, 일반적인 형태 |
| **분산형** | 분석 전문 인력을 **현업 부서에 배치**. 전사 차원 우선순위 + 신속한 실무 적용 (가장 이상적) |

### 5-6. 데이터 거버넌스 ⭐
- 구성 요소 3가지: **원칙(Principle), 조직(Organization), 프로세스(Process)**
- 체계: **데이터 표준화 → 데이터 관리 체계 → 데이터 저장소 관리 → 표준화 활동**
  - 데이터 표준화: 표준 용어 설정, 명명 규칙, **메타데이터** 구축, **데이터 사전** 구축
- 빅데이터 거버넌스 추가 고려: **ILM(데이터 생명 주기 관리)**, 전담 조직(데이터 관리자 = Data Steward)

### 5-7. 분석 과제 관리 프로세스
- **과제 발굴**: 분석 아이디어 발굴 → 과제 후보 제안 → 분석 과제 확정
- **과제 수행**: 팀 구성 → 분석 과제 실행 → 분석 과제 진행 관리 → 결과 공유/개선
