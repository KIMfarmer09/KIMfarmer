### 4-3. 포트폴리오 사분면 분석 ⭐⭐ (매우 자주 출제)
가로축 = **시급성**(현재/미래), 세로축 = **난이도**(어려움/쉬움)

| | 시급성: 현재 (Current) | 시급성: 미래 (Future) |
|---|---|---|
| 난이도: **어려움** | **1사분면** | **2사분면** |
| 난이도: **쉬움** | **3사분면** | **4사분면** |

- **가장 먼저** 할 과제: **3사분면** (급하고 쉬움) / **가장 나중**: **2사분면** (안 급하고 어려움)
- **시급성**을 우선 기준으로 → **3 → 4 → 2**
- **난이도**를 우선 기준으로 → **3 → 1 → 2**

### 5-1. 거버넌스 구성요소 5가지
**조직(Organization), 과제 기획/운영 프로세스(Process), 분석 관련 시스템(System), 데이터(Data), 분석 관련 교육 및 마인드 육성 체계(Human Resource)**

### 5-2. 분석 준비도 (Readiness) — 6가지 영역 ⭐
**분석 업무 파악, 인력 및 조직, 분석 기법, 분석 데이터, 분석 문화, IT 인프라**

### 5-3. 분석 성숙도 (Maturity) ⭐
CMMI 모델 기반, 단계: **도입 → 활용 → 확산 → 최적화**
평가 부문: **비즈니스 부문, 조직·역량 부문, IT 부문**

### 5-4. 준비도 × 성숙도 사분면 ⭐⭐
| | 준비도 **낮음** | 준비도 **높음** |
|---|---|---|
| 성숙도 **높음** | **정착형** | **확산형** |
| 성숙도 **낮음** | **준비형** | **도입형** |

> 💡 외우는 법: 둘 다 낮으면 이제 **준비**, 둘 다 높으면 **확산**. 준비도만 높으면 바로 **도입** 가능, 성숙도만 높으면 **정착**이 필요.

### 5-5. 분석 조직 구조 3가지 ⭐
| 구조 | 특징 |
|---|---|
| **집중형** | 별도 분석 전담 조직이 전사 분석 수행. 현업 부서와 **업무 중복·이원화** 가능성 |
| **기능 중심형** | 각 현업 부서가 **직접** 분석. 전사적 관점 분석이 어려움, 일반적인 형태 |
| **분산형** | 분석 전문 인력을 **현업 부서에 배치**. 전사 차원 우선순위 + 신속한 실무 적용 (가장 이상적) |

### 5-6. 데이터 거버넌스 ⭐
- 구성 요소 3가지: **원칙(Principle), 조직(Organization), 프로세스(Process)**
- 체계: **데이터 표준화 → 데이터 관리 체계 → 데이터 저장소 관리 → 표준화 활동**
  - 데이터 표준화: 표준 용어 설정, 명명 규칙, **메타데이터** 구축, **데이터 사전** 구축
- 빅데이터 거버넌스 추가 고려: **ILM(데이터 생명 주기 관리)**, 전담 조직(데이터 관리자 = Data Steward)

### 5-7. 분석 과제 관리 프로세스
- **과제 발굴**: 분석 아이디어 발굴 → 과제 후보 제안 → 분석 과제 확정
- **과제 수행**: 팀 구성 → 분석 과제 실행 → 분석 과제 진행 관리 → 결과 공유/개선

### 1-1. R 기본 문법 (시험에 나오는 수준만)
```r
x <- c(1, 2, 3)      # c(): 값을 묶어 "벡터"(한 줄짜리 데이터) 만들기, <- 는 "저장"
x * 2                # 2 4 6  (벡터는 원소마다 계산됨)
x[2]                 # 2      (R은 번호가 1부터 시작! 파이썬은 0부터)
df <- data.frame(이름=c("A","B"), 점수=c(90, 80))  # 표(엑셀 시트 같은 것)
head(df); str(df); summary(df)  # 앞부분 보기 / 구조 보기 / 요약 통계
```
- 자료형: 숫자형(numeric), 문자형(character), 논리형(TRUE/FALSE), 범주형(**factor**)
- 자료구조: 벡터(한 종류만), 행렬(matrix), **데이터프레임**(열마다 종류가 달라도 됨), 리스트(아무거나 담는 상자)
- 결측값 **NA**, 결측 확인 `is.na()`, 결측 제외 계산 `mean(x, na.rm=TRUE)`

### 1-2. 결측값 처리 ⭐
| 방법 | 설명 |
|---|---|
| **완전 분석법** (삭제) | 결측이 있는 행을 통째로 삭제 — 간단하지만 데이터 손실 |
| **평균 대치법** | 평균으로 채움 — 간단하지만 분산이 작아지는 문제 |
| **단순 확률 대치법** | 확률적으로 뽑은 값으로 채움 (**Hot-deck**, Nearest Neighbor 등) |
| **다중 대치법** | 여러 번 대치 → 분석 → 결합 (**대치 → 분석 → 결합** 3단계) |

### 1-3. 이상값(Outlier) 판단 ⭐
- **ESD**: 평균 ± **3 × 표준편차** 밖이면 이상값
- **사분위수(상자그림)**: `Q1 − 1.5×IQR` 보다 작거나 `Q3 + 1.5×IQR` 보다 크면 이상값 (IQR = Q3 − Q1)
- 이상값이라고 무조건 삭제하지 않음! (예: 부정 사용 탐지에서는 이상값이 핵심)
